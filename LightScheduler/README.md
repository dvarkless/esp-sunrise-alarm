# LightScheduler — стартовый каркас (boilerplate)

Рабочая заготовка проекта «Smart Scheduled Light Controller» (ESP32 / ESP8266): плавный «рассвет» по расписанию **на каждый день недели** от DS3231, показания BME280 (температура/давление) и AHT10/AHT20 (влажность) в веб-интерфейсе, управление кнопкой (клик по включённому свету — отложить розжиг на N минут; при выключенном свете клик игнорируется; удержание ≥ 2 с — пропустить сегодняшний розжиг) и энергонезависимое хранение настроек в LittleFS.

## Структура

```
LightScheduler/
├── LightScheduler.ino   // setup() + неблокирующий loop(), расписание и состояние кнопки
├── board.h              // платформенный слой: выбор платы (LS_BOARD_*), пины, различия ШИМ/WiFi
├── config.h / .cpp      // Config (расписание по дням) + Saver (LittleFS, Atomic); пины — в board.h
├── sensors.h / .cpp     // BME280 (температура/давление) + AHT10/20 (влажность) и DS3231 (+ день недели и ключ даты)
├── light.h / .cpp       // плавный розжиг (ШИМ: LEDC/analogWrite), перцептуальная кривая CURVE_LUT, флаг включения
├── button.h / .cpp      // EncButton: клик и удержание 2 с
├── webui.h / .cpp       // веб-интерфейс настроек (Settings) + WiFi
└── log.h / .cpp         // общий логгер: Serial + веб-виджет Log (sets::Logger)
```

## Установка библиотек (Arduino IDE)

`Sketch → Include Library → Manage Libraries`, установить:

| Библиотека | Назначение |
|---|---|
| **Settings** | веб-интерфейс настроек (класс `SettingsGyver`). ⚠️ В старых материалах называлась **SettingsGyver** — сейчас пакет называется **Settings**. |
| **Saver** | хранение Config в LittleFS (атомарная запись) |
| **EncButton** | обработка кнопки (потребует **GyverIO**, ставится автоматически) |
| **GyverBME280** | драйвер BME280 (температура, давление; IIR-фильтр x16 задаётся явно) |
| **Adafruit AHTX0** | драйвер AHT10/AHT20 (влажность); подтянет **Adafruit BusIO** и **Adafruit Unified Sensor** |
| **GyverDS3231** | драйвер DS3231 (потребует **Stamp**, ставится автоматически) |

Библиотека **Settings** имеет зависимости (GTL, GyverDB, StringUtils, GyverHTTP, BSON, Stamp, Table, StreamIO) — при установке из менеджера библиотек они подтягиваются автоматически.

## Плата

Поддерживаются **ESP32** и **ESP8266**; платформа определяется выбранным ядром, различия скрыты в `board.h` (пины) и `light.cpp` (ШИМ).

1. `Tools → Board → Boards Manager` → установить **esp32 by Espressif Systems** и/или **esp8266 by ESP8266 Community**.
2. Выбрать плату **ESP32 Dev Module** или **NodeMCU 1.0 / Wemos D1 mini**.
3. Для ESP32: `Tools → Partition Scheme` → схема с LittleFS/SPIFFS, например **Default 4MB with spiffs** (нужно место под `/config.cfg`). На ESP8266 LittleFS доступен в стандартной разметке (4 МБ).
4. Нужно ядро **esp32 by Espressif Systems ≥ 3.0** (проверено на 3.3.0): прошивка использует LEDC API ядра 3.x (`ledcAttachChannel`/`ledcWriteChannel`); в core 3.0 вызовы `ledcSetup`/`ledcAttachPin`/`ledcWrite(channel, …)` удалены. Для ESP8266 — ядро **esp8266 by ESP8266 Community 3.x** (проверено на 3.1.2): используется `analogWriteFreq`/`analogWriteRange`/`analogWrite`, LEDC там нет.

## Настройка

- **Пины** — в `board.h` (`PIN_PWM_LED`, `PIN_I2C_SDA`, `PIN_I2C_SCL`, `PIN_BUTTON`); значения свои для ESP32 и ESP8266.
- **Wi-Fi** — в `config.h` (`WIFI_SSID` / `WIFI_PASS`). Если SSID оставить пустым, устройство поднимет точку доступа `LightScheduler` (IP по умолчанию `192.168.4.1`).
- **Часовой пояс** — `TIME_ZONE` в `config.h` (для Москвы `3`).
- **Значения по умолчанию** — поля структуры `Config` в `config.h`: расписание по дням (`days[7]`, 0=Пн…6=Вс, по умолчанию все дни 07:30), `fadeDuration` (мин, по умолчанию 15), `turnOffDelay` (мин, по умолчанию 60), `snoozeMinutes`.
- **Кривая розжига** — фиксированная перцептуальная (50 % прогресса → ≈30 % скважности ШИМ); формула, таблица и обоснование — в [`docs/light-curve.md`](../docs/light-curve.md).
- **Датчики** — BME280 на общей шине I2C (`BME280_ADDR`, по умолчанию `0x77`, возможен `0x76`) для температуры и давления; AHT10/AHT20 (`0x38`, альтернативный `0x39` — константа `AHT_ADDR` в `sensors.cpp`) для влажности. Если AHT не найден, влажность автоматически берётся с BME280.
- **Фильтрация BME280** — IIR-фильтр x16 (`FILTER_COEF_16`) включается явно в `sensors.cpp`: `bme.setFilter(...)` до `begin()`; это же значение — библиотечное по умолчанию, коэффициент можно поменять (0=выкл, 1=×2 … 4=×16).

## Прошивка и веб-интерфейс

1. Откройте `LightScheduler.ino` в Arduino IDE (все `.h/.cpp` должны лежать в этой же папке).
2. Прошейте плату, откройте Serial Monitor (115200).
3. После подключения к сети откройте в браузере IP-адрес устройства (указан в Serial-мониторе) — появится веб-интерфейс настроек.

> Сборка проверена реальным тулчейном `arduino-cli 1.5.1` для обеих платформ: `arduino-cli compile --fqbn esp32:esp32:esp32 LightScheduler/` (ядро `esp32:esp32 3.3.0`, flash ≈85 %, RAM ≈15 %) и `arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 LightScheduler/` (ядро `esp8266:esp8266 3.1.2`, flash ≈36 %, RAM ≈39 %, IRAM ≈95 % — на ESP8266 IRAM узкое место).

## Логика

- **Расписание** — в главном цикле раз в секунду сверяется время DS3231 с расписанием текущего дня (`config.days[weekday-1]`): учитываются общий выключатель `config.enabled`, флаг дня `day.enabled`, час/минута, а также пропуск сегодняшнего дня. При совпадении запускается `light_startFadeIn()`.
- **Розжиг** — ШИМ (LEDC на ESP32, `analogWrite` на ESP8266) поднимает скважность на `PIN_PWM_LED` от 0 до 255 за `config.fadeDuration` минут по перцептуальной кривой `p^1.73697` (таблица `CURVE_LUT[256]`): 50 % прогресса дают ≈30 % скважности, рантайм — только целочисленный. После завершения розжига свет горит ещё `config.turnOffDelay` минут, затем гаснет автоматически.
- **Кнопка** — клик срабатывает только при включённом свете (`light_isOn()`: идёт розжиг или лента уже горит): гасит свет и откладывает розжиг на `config.snoozeMinutes` минут (неблокирующий таймер). Если свет выключен, клик игнорируется (только лог в Serial); клик в ожидании отложенного розжига тоже ничего не делает — перезапустить/продлить отсчёт кликом нельзя. Удержание ≥ 2 с гасит свет, отменяет отложенный розжиг и пропускает сегодняшний день (на следующий день расписание работает снова). Клик не отменяет сегодняшнее событие расписания: если отложенный розжиг сработал раньше штатного времени, позже сработает и оно. Ручное мгновенное включение — веб-кнопка «Запуск будильника» (выключение — «Выключить будильник»).
- **Датчики** — температура и давление обновляются раз в секунду с BME280; влажность — с AHT10/AHT20 неблокирующим автоматом (измерение раз в 2 с, `getEvent()` с ожиданием не используется, чтобы не блокировать `loop()`). При отсутствии AHT или устаревании данных (старше 10 с) влажность берётся с BME280. Всё отображается в вебморде (режим без WebSocket, через периодический `onUpdate`).
- **Сохранение** — любое изменение настроек в вебморде пишется прямо в `config`, а Saver в течение ~5–10 с сохраняет структуру в `/config.cfg` (атомарно). При фактической записи в лог пишется время. Версия формата `'C'`: при обновлении прошивки старый `'B'`-файл игнорируется, настройки один раз сбрасываются на значения по умолчанию.
- **Время** — при сброшенном RTC (потеря питания) время берётся из Интернета по NTP (`pool.ntp.org`) после подключения Wi-Fi; дата/время отображаются в вебморде, а старт и сохранение настроек логируются с временем.

## Примечание о расхождении с PROJECT.md

PROJECT.md синхронизирован с текущим кодом, включая расписание по дням недели, перцептуальную кривую розжига и поведение кнопки. Единственное историческое уточнение: библиотека в менеджере библиотек называется **Settings** (класс внутри — `SettingsGyver`), а подключение к Wi-Fi выполняется в коде явно — см. `webui.cpp`. Архитектура (Config → Saver → LittleFS, виджеты по указателям) сохранена в неизменном виде.
