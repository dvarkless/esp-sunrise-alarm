# Smart Scheduled Light Controller (ESP32)

Проект **esp-sunrise-alarm**: устройство на ESP32, которое плавно включает свет в заданное время **по каждому дню недели** (часы DS3231), показывает температуру и давление с BME280 и влажность с AHT10/AHT20 (запасной источник — BME280) в веб-интерфейсе и управляется физической кнопкой: клик по разгорающемуся/включённому свету — отложить розжиг на N минут (клик при выключенном свете игнорируется), удержание ≥ 2 с — пропустить сегодняшний розжиг. Скважность ШИМ растёт по перцептуальной (логарифмической по восприятию) кривой.

Документ описывает **фактическое** состояние репозитория: структуру файлов, модули прошивки, пины, библиотеки и поведение кода.

## Аппаратное обеспечение

| Компонент | Назначение |
|---|---|
| ESP32 Dev Board | Основной контроллер |
| PWM LED-контроллер (MOSFET/драйвер) | Управление яркостью ленты/лампы |
| BME280 | Температура и давление (IIR-фильтр x16, см. модуль `sensors`) |
| AHT10 / AHT20 | Влажность (общая шина I2C, адрес `0x38`, альтернативный `0x39`) |
| DS3231 (RTC) | Часы реального времени с батарейной подпиткой |
| Тактовая кнопка | Ручное управление: клик по включённому свету — отложить, удержание — пропустить день |
| Блок питания 3.3V / 5V | Питание платы и периферии |

### Пины (из [`config.h`](LightScheduler/config.h))

| Определение | Значение | Подключение |
|---|---|---|
| `PIN_PWM_LED` | GPIO 5 | Вход MOSFET/драйвера, общий GND с ESP32 |
| `PIN_I2C_SDA` | GPIO 21 | Общая шина BME280 + AHT10/20 + DS3231 |
| `PIN_I2C_SCL` | GPIO 22 | Общая шина BME280 + AHT10/20 + DS3231 |
| `PIN_BUTTON` | GPIO 27 | Второй вывод на GND, `INPUT_PULLUP` |

Адреса на общей шине I2C: `BME280_ADDR = 0x76` (альтернатива `0x77`), `RTC_ADDR = 0x68` (константа носит справочный характер: `rtc.begin()` из GyverDS3231 обращается к адресу по умолчанию), адрес AHT10/AHT20 `0x38`/`0x39` задан константой `AHT_ADDR` в [`sensors.cpp`](LightScheduler/sensors.cpp).

### Прочие константы

| Константа | Значение | Смысл |
|---|---|---|
| `PWM_FREQ` | 25000 Гц | Частота LEDC |
| `PWM_RES` | 8 бит | Диапазон скважности 0…255 |
| `PWM_CHANNEL` | 0 | Канал LEDC |
| `FADE_STEP_MS` | 500 мс | Период шага розжига |
| `TIME_ZONE` | 3 | Часовой пояс для DS3231 (`setStampZone`) |
| `WIFI_SSID` / `WIFI_PASS` | `""` / `""` | Учётные данные сети; пустой SSID → точка доступа |
| `AP_NAME` | `"LightScheduler"` | Имя точки доступа |

## Программная архитектура

Главный файл содержит только `setup()` и неблокирующий `loop()`, который опрашивает тикеры модулей. Модули общаются через простые функции из `.h`-файлов; общего класса-синглтона или событийной шины нет.

```text
                     ┌──────────────────────────┐
                     │  LightScheduler.ino      │
                     │  loop(): тикеры + распис.│
                     └───┬───────┬───────┬──────┘
        config_tick() ───┘       │       └─── webui_tick()
                                 │
        ┌────────────┬───────────┼───────────┬────────────┐
        ▼            ▼           ▼           ▼            ▼
   ┌─────────┐ ┌──────────┐ ┌────────┐ ┌─────────┐ ┌──────────┐
   │ config  │ │ sensors  │ │ light  │ │ button  │ │  webui   │
   │+ Saver  │ │BME/AHT   │ │ LEDC   │ │EncButton│ │ Settings │
   └────┬────┘ └──────────┘ └────────┘ └─────────┘ └──────────┘
        │                     ▲            │             │
        │ изменяет config     └────────────┴─────────────┘
        └──────────► /config.cfg (LittleFS, Atomic)
```

### `config` — [`config.h`](LightScheduler/config.h) / [`config.cpp`](LightScheduler/config.cpp)

Единый источник правды для настроек (расписание по дням недели):

```cpp
// Расписание одного дня недели
struct DaySchedule {
    uint8_t hour    = 7;     // 0-23
    uint8_t minute  = 30;    // 0-59
    bool    enabled = true;  // день участвует в расписании
};

struct Config {
    bool        enabled       = true;   // мастер-выключатель расписания
    uint8_t     snoozeMinutes = 10;     // «отложить» кликом, мин (1-60)
    DaySchedule days[7];                // [0]=Пн … [6]=Вс (ISO 8601)
    uint32_t    fadeDuration  = 15;     // длительность плавного розжига, мин (0-60)
    uint32_t    turnOffDelay  = 60;     // время свечения до автовыключения, мин (0-60)
};
extern Config config;  // sizeof(Config) = 32 байта
```

Функции: `config_setup()` (`LittleFS.begin(true)` + `saver.begin()`), `config_tick()` (`saver.tick()`), `config_save()` (`saver.write()`).

Сохранение: `SaverFile saver(LittleFS, "/config.cfg", config, 'C', 10, FileStore::Atomic)` — версия формата `'C'`, автосохранение (проверка CRC с периодом `timeout/2`, т.е. примерно через 5–10 с после последнего изменения), атомарная замена файла (защита от сбоя питания). При фактической записи в `config_tick()`/`config_save()` в лог пишется время «Настройки сохранены: <дата> <время>».

> **Миграция формата:** версия поднята с `'B'` до `'C'`, потому что структура несовместима (`fadeDuration` переведён из миллисекунд в минуты и добавлено поле `turnOffDelay`, структура выросла 28 → 32 байта). При несовпадении версии или размера заголовка Saver считает данные из RAM значениями по умолчанию и перезаписывает `/config.cfg` — старые настройки один раз сбрасываются на значения по умолчанию (все 7 дней 07:30, включено).

### `sensors` — [`sensors.h`](LightScheduler/sensors.h) / [`sensors.cpp`](LightScheduler/sensors.cpp)

| Функция | Поведение |
|---|---|
| `sensors_setup()` | `Wire.begin(SDA, SCL)`, `setStampZone(TIME_ZONE)`, `rtc.begin()`; при `rtc.isReset()` логирует «RTC был сброшен» (время возьмётся по NTP); `bme.setFilter(BME_FILTER_MODE)` **до** `bme.begin(BME280_ADDR)`; `aht.begin(&Wire, 0, AHT_ADDR)` с логом «найден/не найден» |
| `sensors_ntp_sync()` | Если RTC не синхронизирован — берёт время из Интернета (`configTime` + `getLocalTime` по `pool.ntp.org`, таймаут 5 с) и пишет его в DS3231 через `rtc.setTime(...)`. Вызывается из `webui_setup()` после подключения Wi-Fi |
| `sensors_tick()` | Возвращает `true` раз в секунду (`rtc.tick()`); обновляет кэш BME280 (температура/давление) и влажность (AHT; при отсутствии/устаревании — BME280). AHT опрашивается неблокирующим автоматом в этом же тике. При несинхронизированном RTC всегда `false` |
| `sensors_ok()` | Флаг успешной инициализации BME280 |
| `sensors_temperature()` / `sensors_pressure()` | Кэшированные значения BME280; давление пересчитано из Па в гПа (`/100.0f`) |
| `sensors_humidity()` | Влажность, %: основной источник — AHT10/AHT20; если AHT не найден или данные старше 10 с — запасной источник BME280 |
| `sensors_hour()` / `sensors_minute()` | Текущее время по DS3231 (из кэша StampKeeper) |
| `sensors_date_str()` / `sensors_time_str()` | Строки даты/времени RTC (для веб-виджетов «Дата»/«Время» и логов) |
| `sensors_weekday()` | День недели по RTC: `1` = Пн … `7` = Вс (ISO 8601, `Datime::weekDay()`); при несинхронизированном RTC возвращает `1` |
| `sensors_date_key()` | Ключ календарного дня `ГГГГММДД` (например, `20261102`); `0` при несинхронизированном RTC. Используется для «пропуска сегодня» и смены суток |

**AHT10/AHT20 — источник влажности.** Влажность опрашивается **неблокирующим автоматом** прямо в `sensors_tick()`: раз в 2 с выдаётся команда запуска измерения (`0xAC 0x33 0x00`), затем раз в 100 мс читается байт статуса (бит `0x80` — «занято»), после готовности читаются 6 байт данных, влажность считается как `raw20·100/2²⁰` (`raw20 = data[1]<<12 | data[2]<<4 | data[3]>>4`). Библиотечный `Adafruit_AHTX0::getEvent()` (блокирующее ожидание ≈80 мс через `delay`) намеренно не используется, чтобы не блокировать `loop()`. Таймаут измерения — 500 мс. Если AHT не инициализировался или последнее удачное измерение старше 10 с, влажность берётся с BME280 (запасной источник); в Serial при старте пишется предупреждение.

**Фильтрация BME280.** В `sensors_setup()` IIR-фильтр датчика задаётся явно: `bme.setFilter(BME_FILTER_MODE)` **до** `bme.begin()` (GyverBME280 записывает коэффициент в регистр `0xF5` внутри `begin()`, поэтому порядок обязателен). `BME_FILTER_MODE = FILTER_COEF_16` (код `0x04`; `0`=выкл, `1`=×2, `2`=×4, `3`=×8, `4`=×16) — это же значение является библиотечным по умолчанию, поэтому поведение сохранено, но фильтр теперь задан явно и настраивается в одном месте. Константы `BME_FILTER_MODE` и `AHT_ADDR` объявлены в [`sensors.cpp`](LightScheduler/sensors.cpp).

### `light` — [`light.h`](LightScheduler/light.h) / [`light.cpp`](LightScheduler/light.cpp)

| Функция | Поведение |
|---|---|
| `light_setup()` | `ledcAttachChannel(PIN_PWM_LED, PWM_FREQ, PWM_RES, PWM_CHANNEL)` (LEDC API ESP32 core 3.x) + гашение |
| `light_startFadeIn()` | Запуск розжига: `on = true` (свет включён сразу), `fadeStart = millis()`, `lastStep = fadeStart`, `ledcWriteChannel(PWM_CHANNEL, 0)` |
| `light_stop()` | Мгновенное гашение и остановка fade (`on = false`) |
| `light_update()` | Неблокирующий шаг не чаще `FADE_STEP_MS`: `elapsed = now - fadeStart`, `idx = elapsed*255/(fadeDuration*60*1000)`, скважность = `CURVE_LUT[idx]`; целочисленно, без float. По завершении розжига `fading = false`, `on` остаётся `true`; затем отсчитывается `turnOffDelay` минут и вызывается `light_stop()` (автовыключение) |
| `light_active()` | `true`, пока идёт розжиг (после завершения — `false`) |
| `light_isOn()` | `true`, если свет включён: с `light_startFadeIn()` до `light_stop()`, включая завершённый розжиг |

**Кривая розжига — перцептуальная.** Раньше скважность росла линейно (`0→255`), из-за чего свет «рывком» появлялся в начале. Теперь используется `d(p) = p^γ`, где `γ = ln(0.30)/ln(0.50) ≈ 1.7369656`: **50 % прогресса розжига дают ≈30 % скважности** (`LUT[128] = 77` из 255, т.е. ≈30.2 %). Кривая реализована как `static const uint8_t CURVE_LUT[256]` (256 байт во flash; на ESP32 `const` и так лежит во flash), индекс — прогресс 0…255. Рантайм только целочисленный; накопления с плавающей точкой нет, поэтому нет дрейфа. Первый ненулевой уровень — `LUT[8]` (≈3.1 % длительности, при округлении half-up). 8-битный ШИМ сохранён. Обоснование, сравнение моделей восприятия (Стивенс, sRGB, CIE L\*), таблица и offline-генератор — в [`docs/light-curve.md`](docs/light-curve.md).

**Состояние света.** `light_isOn()` — «свет включён»: `true` с `light_startFadeIn()` (сразу, ещё до первого шага ШИМ) до `light_stop()`, включая случай, когда розжиг уже завершён и лента горит на максимуме. `light_active()` при этом остаётся «идёт розжиг» (`false` после завершения). По `light_isOn()` `.ino` решает, реагировать ли на клик кнопки: при выключенном свете клик — no-op.

### `log` — [`log.h`](LightScheduler/log.h) / [`log.cpp`](LightScheduler/log.cpp)

Единая точка логирования. `log_print` / `log_println` / `app_log_printf` пишут **одновременно** в `Serial` и в кольцевой буфер `sets::Logger logger(1024)`, который отдаётся в браузер виджетом `Log` (последний элемент страницы, `ID_LOG = 4`) через `upd.update(ID_LOG, logger)` — работает в режиме опроса без WebSocket. Все прежние `Serial.*`-вызовы в `.ino`, `sensors.cpp` и `webui.cpp` переведены на эти обёртки; `Serial.begin(115200)` остался. Префикс `app_` у `app_log_printf` — чтобы не конфликтовать с `int log_printf()` из ядра ESP32 (`esp32-hal-log.h`).

## Логика работы

1. **`setup()`** вызывает `config_setup → sensors_setup → light_setup → button_setup → webui_setup`.
2. **`loop()`** (без блокировок): `config_tick()`, `light_update()`, `button_tick()`, `webui_tick()`; затем обработка кнопки, расписание раз в секунду и неблокирующий таймер «отложенного» розжига.
3. **Кнопка:**
   - **клик** — срабатывает только если свет включён (`light_isOn()`, т.е. идёт розжиг или лента уже горит): `light_stop()`, отмена предыдущего отсчёта, `snoozeStartMs = millis()`, `snoozePending = true` — розжиг запустится через `config.snoozeMinutes` минут. Если свет выключен, клик игнорируется (лог в Serial, состояние не меняется): «откладывать» нечего, штатное расписание позже сработает как обычно. Мгновенного розжига по клику нет — ручное включение осталось в веб-интерфейсе кнопкой «Запуск будильника»;
   - **удержание ≥ 2 с** — `light_stop()`, отмена «отложенного» розжига, `skipDateKey = sensors_date_key()`: сегодняшний розжиг пропускается. Пропуск хранится только в RAM и привязан к дате, поэтому следующий день срабатывает как обычно; постоянного отключения расписания нет.
4. **Расписание** — раз в секунду, по `sensors_tick()`:
   - состояние хранится в `.ino`: `alarmTriggered` (сработало в текущую минуту) и `lastMinute` (последняя обработанная минута);
   - при смене минуты `alarmTriggered` сбрасывается; смена суток всегда меняет минуту (23:59→00:00), поэтому следующий день не может «подавить» своё событие;
   - день недели: `sensors_weekday()` (1=Пн…7=Вс) → индекс `config.days[weekday-1]`;
   - срабатывание: `config.enabled && day.enabled && !alarmTriggered && !snoozePending && sensors_date_key() != skipDateKey && hour == day.hour && minute == day.minute` → `light_startFadeIn()` + `alarmTriggered = true`.
5. **«Отложенный» розжиг** — неблокирующий таймер по `millis()`: при `millis() - snoozeStartMs >= max(1, snoozeMinutes) * 60000` → `light_startFadeIn()`, `snoozePending = false`, `alarmTriggered = true`. Отсчёт не зависит от `config.enabled` и включённости дня (это ручной override). Повторный клик по включённому свету перезапускает отсчёт; клик при выключенном свете игнорируется. Проверка таймера стоит **после** блока расписания: если дедлайн попадает ровно на минуту расписания, расписание в этой итерации ещё видит `snoozePending == true` и не срабатывает — розжиг происходит один раз.
6. **Розжиг** — `light_update()` раз в 500 мс: скважность растёт по `CURVE_LUT` от 0 до 255 за `config.fadeDuration` минут; по достижении 255 fade останавливается (`light_active() == false`), но свет остаётся включённым (`light_isOn() == true`), а через `config.turnOffDelay` минут `light_update()` вызывает `light_stop()` — автовыключение. `fadeDuration = 0` — максимум на первом шаге (≤ `FADE_STEP_MS`); `turnOffDelay = 0` — автовыключение сразу после розжига.
7. **Веб-кнопки** — «Запуск будильника» (`light_startFadeIn()`) и «Выключить будильник» (`light_stop()`) напрямую, флаги `alarmTriggered`/отсчёта/пропуска не трогают.

### Нюансы реализации

- `snoozePending`, `snoozeStartMs`, `skipDateKey` — состояние в RAM: после перезагрузки «отложенный» розжиг и пропуск дня сбрасываются, расписание снова работает по конфигу.
- Клик **не отменяет** сегодняшнее событие расписания: если «отложенный» розжиг сработал раньше штатного времени дня, позже сработает и штатное событие (розжиг начнётся заново с нуля). Для полной отмены сегодняшнего дня используется удержание ≥ 2 с.
- Клик при **выключенном** свете — no-op: не гасит, не запускает и не отменяет отсчёт (только запись в Serial). Поэтому клик до штатного времени ничего не откладывает и не подавляет — расписание позже сработает как обычно. То же относится к клику в ожидании «отложенного» розжига: перезапустить/продлить отсчёт кликом нельзя (только удержание ≥ 2 с или ожидание).
- Клик при включённом/разгорающемся свете гасит его и запускает новый отсчёт `config.snoozeMinutes`.
- `light_stop()` сам по себе не сбрасывает `alarmTriggered`; флаг сбрасывается только по смене минуты (и устанавливается при срабатывании расписания или «отложенного» таймера).
- Если RTC не синхронизирован, `sensors_tick()` не возвращает `true`, поэтому расписание не работает; `sensors_weekday()`/`sensors_date_key()` возвращают безопасные заглушки (`1`/`0`).
- Время RTC при `rtc.isReset()` берётся из Интернета по NTP (в `webui_setup()`, только при подключённом Wi-Fi); если Интернета нет, RTC остаётся несинхронизированным и расписание не работает.
- SSID/пароль Wi-Fi в коде константами — отдельного экрана настройки сети нет.
- Влажность идёт с AHT10/AHT20 (обновление раз в 2 с, неблокирующе); до первого успешного измерения, при отсутствии AHT или при данных старше 10 с используется влажность BME280, поэтому в веб-интерфейсе значение не «зависает» и не обнуляется.
- IIR-фильтр BME280 (x16) сглаживает температуру и давление, но замедляет реакцию на резкие изменения — это осознанный компромисс; коэффициент задаётся `BME_FILTER_MODE` в `sensors.cpp`.
- После прошивки с версией формата `'C'` старый `/config.cfg` (формат `'B'`) не читается: настройки один раз сбрасываются на значения по умолчанию.

## Веб-интерфейс

Поднимается библиотекой **Settings** (класс `SettingsGyver`, заголовок `<SettingsGyver.h>`), сервер на порту 80. Открывается по IP устройства, выведенному в Serial (`192.168.4.1` в режиме точки доступа). Виджеты подключены к полям `config` по указателям, поэтому правки из браузера сразу меняют структуру, а Saver затем сохраняет её в `/config.cfg`. Подписи виджетов уникальны по всей странице (Settings адресует виджеты по label); дни недели — строки (`Row`) внутри группы «Расписание».

| Группа | Виджет | Поле / действие |
|---|---|---|
| Расписание | `Switch` «Расписание включено» — мастер-выключатель | `config.enabled` |
| Расписание | 7 строк «Пн»…«Вс»: `Switch` «Включено (X)» | `config.days[i].enabled` |
| Расписание | `Spinner` «Часы», 0…23, шаг 1 | `config.days[i].hour` |
| Расписание | `Spinner` «Минуты», 0…55, шаг 5 | `config.days[i].minute` |
| Розжиг | `Slider` «Длительность (мин)», 0…60, шаг 1, единица `мин` | `config.fadeDuration` |
| Розжиг | `Button` «Запуск будильника» / «Выключить будильник» | `light_startFadeIn()` / `light_stop()` |
| Кнопка | `Slider` «Отложить (мин)», 1…60, шаг 1 | `config.snoozeMinutes` |
| Кнопка | `Slider` «Время свечения (мин)», 0…60, шаг 1 | `config.turnOffDelay` |
| Датчики | `Label` «Дата» / «Время» + `LabelFloat` «Температура» / «Влажность» / «Давление», 1 знак | ID 3/4 + ID 1/2/5, только чтение |
| — | `Log` «Лог» — последний элемент страницы; зеркало Serial-логов | ID 6, `sets::Logger` |

Показания датчиков обновляются через `onUpdate(update)` — режим периодического опроса, без WebSocket. Строки «Пн»…«Вс» реализованы `sets::Row` внутри группы «Расписание»: Settings 1.4.3 молча отбрасывает вложенные группы, а строки внутри группы рендерятся нормально (в текущей Settings `Tabs` — value-виджет, а не контейнер). Последним элементом страницы стоит виджет `Log` — в него зеркалится весь Serial-вывод (`log.h`/`log.cpp`, буфер `sets::Logger`).

## Сборка и прошивка

1. Установить **esp32 by Espressif Systems** (Boards Manager) и выбрать плату **ESP32 Dev Module**.
2. Установить библиотеки из таблицы выше (`Sketch → Include Library → Manage Libraries`).
3. `Tools → Partition Scheme` — схема с LittleFS, например **Default 4MB with spiffs** (нужно место под `/config.cfg`).
4. Открыть [`LightScheduler.ino`](LightScheduler/LightScheduler.ino); все `.h/.cpp` уже лежат в той же папке.
5. Прошить, открыть Serial Monitor на 115200 — в логе будут версия, статусы датчиков, RTC и IP-адрес веб-интерфейса.

**Проверка сборки (реальный тулчейн):** `arduino-cli 1.5.1`, ядро `esp32:esp32 3.3.0`, библиотеки из таблицы выше (включая Adafruit AHTX0/BusIO/Unified Sensor). Команда `arduino-cli compile --fqbn esp32:esp32:esp32 LightScheduler/` завершается успешно (проверено после добавления AHT-влажности и фильтра): flash 1 097 051 из 1 310 720 байт (83 %), RAM 49 028 из 327 680 байт (14 %), предупреждений из кода проекта нет.

> **Требование к ядру ESP32:** прошивка использует LEDC API ядра 3.x — `ledcAttachChannel()` / `ledcWriteChannel()`. В core 3.0 legacy-вызовы `ledcSetup`/`ledcAttachPin`/`ledcWrite(channel, …)` удалены, поэтому нужно ядро **esp32 by Espressif Systems ≥ 3.0** (проверено на 3.3.0).

Настройка под свою схему — константы и значения по умолчанию в [`config.h`](LightScheduler/config.h), Wi-Fi — `WIFI_SSID`/`WIFI_PASS`/`AP_NAME` там же.

> После первого запуска прошивки с форматом `'C'` старые настройки из `/config.cfg` сбрасываются на значения по умолчанию (все дни 07:30, расписание включено).

## Возможные расширения

- Deep Sleep с пробуждением по SQW DS3231 для экономии энергии.
- История показаний датчиков в LittleFS.
- Перенос сборки на PlatformIO и добавление CI-проверки компиляции.
- 10-битный ШИМ (или dithering) для более плавной кривой на низких уровнях: сейчас первый ненулевой уровень — `LUT[8]`, шаг `0→1` при 8-битном ШИМ даёт заметный (≈16 % по модели Стивенса) скачок воспринимаемой яркости.
- Плавное затухание (fade-out) и/или настройка формы кривой (гаммы) из веб-интерфейса.
- Настройка источника влажности (AHT/BME280) и калибровки AHT из веб-интерфейса. Добавление температуры с AHT (сейчас используется только влажность; температура остаётся за BME280).
